### 1. Encapsulation

Encapsulation helps in implementing business logic before updating the record. By locking stock levels and prices behind private variables, it could protect crucial store data. Also, all changes must pass through controlled methods instead of allowing the cashier or something to overwrite the stock numbers. 

### 2. Abstraction

Abstraction helps in simplifying the sale system by hiding complex internal math and operational rules behind straightforward codes. For example, when a cashier needs to scan an item, navigating formulas for specific things like unit converions, taxes and more isn't needed to be executed by the main program. It can just simple call a single method. The individual product just performs all the calculations silently in the background, allowing the screen to be clean and easy to read.

### 3. Inheritance

Inheritance can help by finding codes that is repeated then eliminates it. It helps by only needing to write a code for what makes that specific category unique like kilogram weight units and more, ensuring that updates is only needed to be made in one area.

### 4. Polymorphism

Polymorphism helps in processing different types of products using a single action. For example, by giving every product class a shared method name, the program can use it to put items like rice, glass coke bottle into a single list and process them using one simple loop. 

## Reflection

Object-Oriented Programming is really helpful by changing long and messy sequences of codes or instructions into a neat, readable and managable system. Among the four pillars of OOP, I think that Encapsulation is the most useful in improving the sari-sari store inventory system because it addresses the most common problem straightforward. Without it, any part of the software can cause overwritten product data leading to missing records or possibly have price overrides.
